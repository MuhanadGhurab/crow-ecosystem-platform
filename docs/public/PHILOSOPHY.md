## Core beliefs

### 1. Coherence is the product

Random dashboards do not make a platform. A **governed lifecycle** does:

```text
Request → Discovery → Blueprint → Proposal → Go-live → Operations
```

### 2. Blueprint is the contract

The Blueprint binds architecture, pricing, RBAC intent, SAREA scope, readiness, and provisioning — not a slide deck after the sale.

### 3. RBAC ≠ SAREA

```text
RBAC controls access.
SAREA controls experience.
```

Security answers *who may act*. Experience answers *how work should feel*. Never collapse them.

### 4. Truth before scale

```text
Earn the cloud.
```

Local proof (seeds, E2E, notifications) before Azure bills. Cloud is wiring, not a rebuild.

### 5. Sharper economics

Band-based SAR bundles (ops + security + adaptive UX) vs per-seat multiplication — especially for 50–250 employee GCC enterprises. Illustrative advantage vs Odoo/Zoho stacks; binding numbers always in Blueprint.

### 6. Roles ease auth and UI

One **Microsoft Entra** identity from client portal to tenant. RBAC assigns hats. SAREA adapts surfaces. Users do not re-learn three products.

## Guardrails — avoid architecture inflation

The next risk is **too broad**, not too small:

| Avoid | Prefer |
|-------|--------|
| Infinite lifecycle states | Clear pipeline stages |
| AI everywhere marketing | AI as quoted Blueprint extras |
| Module sprawl before customer #2 | MEEM-depth, then template |
| Fake enterprise complexity | Honest demo labels |
| Public provisioning internals | Conceptual readiness gates |
| Cloud theater before local E2E | Local-first sign-off |

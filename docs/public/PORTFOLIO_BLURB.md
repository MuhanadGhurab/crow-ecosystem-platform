# Portfolio blurb (public-safe)

Copy-ready text for CV, GitHub, LinkedIn, and interviews. **Do not** claim production launch, certifications, or live payments unless separately true.

---

## One-line (CV / GitHub tagline)

**Crow Ecosystem Platform** — adaptive enterprise orchestration combining CEM operations, CyberCrow security and evidence readiness, and SAREA role-based experience across a governed Discovery → Blueprint → tenant lifecycle.

---

## Short GitHub description

Multi-tenant Next.js platform for governed enterprise onboarding: public intake, operator discovery, blueprint readiness, and tenant runtime with CyberCrow trust surfaces and SAREA adaptive UX. Staging-validated scenarios (logistics, construction, aviation-style paths). Cost-controlled development — no production launch claim.

---

## Interview explanation (≈45 seconds)

“I built Crow Ecosystem as a reference platform for how Saudi and GCC enterprises could move from a first implementation request to live operations without treating ERP as a module dump on day one. The pipeline is Request, Discovery, Blueprint, then provisioned tenant runtime. Three engines share the tenant: CEM for operations, CyberCrow for security posture and evidence readiness — advisory, not a certified GRC product — and SAREA so executives and dispatchers don’t share the same dashboard. It’s implemented on Next.js, Prisma, and Postgres with Supabase Auth and Entra readiness. I validated multiple tenant stories on staging; the public repo is portfolio-safe with mock mode for local demos.”

---

## Technical bullets

- Next.js 15 App Router, React 19, TypeScript, Tailwind CSS
- PostgreSQL + Prisma; multi-tenant slug routing
- Supabase Auth; Microsoft Entra and Google sign-in paths
- Server actions with RBAC; platform admin vs tenant scopes
- Discovery templates, blueprint readiness, idempotent go-live bridge
- CyberCrow: security events, incidents, audit logs, evidence catalog, GRC mapping (rule-based, advisory)
- SAREA Studio: layouts, navigation, profiles, role mapping, preview impact (F20)
- Public mirror excludes `docs/internal`; no secrets in repo

---

## Architecture bullets

- **CEM** — modular ERP-style workspace per tenant
- **CyberCrow** — trust orchestration visible on tenant, not hidden in ops
- **SAREA** — RBAC for access; SAREA for experience density
- **Lifecycle** — Request → Discovery → Blueprint → Go-live → continuous improvement
- **Isolation** — tenant-scoped data; second-tenant validation (e.g. construction vs logistics modules)

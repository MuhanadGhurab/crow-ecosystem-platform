## Seven-question model

Every material change must answer:

1. Which Product Pillar does the change support?
2. What verified problem does it solve?
3. Why is it required now?
4. What will it delay or replace?
5. What is its data, security and privacy impact?
6. What is its impact on architecture, learning, state and scoring?
7. How will success be measured and how can the change be reversed?

## Allowed outcomes

- Approve Now
- Schedule Later
- Research First
- Idea Vault
- Reject

## Change classes

| Class | Examples |
|-------|----------|
| Foundational | Constitution, audience, anti-pay-to-win, assurance model |
| Architectural | Modular monolith boundaries, identity provider choice after validation |
| Product Enhancement | New Route, Live Sky event type within scope |
| Cosmetic or Content | Copy, illustration, non-scoring content refresh |

## Implementation gate

No Feature enters Product Code without Scope Traceability and an approved Change Request when it alters LOCKED baseline items.

## Purpose

Any proposed Scope change must assess impact before approval.

## Required assessment dimensions

| Dimension | Questions |
|-----------|-----------|
| Product Pillars | Which Pillar(s)? Or none (reject)? |
| User journey | Which phases change? |
| Screens and states | Which screen families / states? |
| Learning Graph | Edges, prerequisites, catalogue? |
| Progression | XP, Mastery, Prestige, Trust effects? |
| Commercial access | Plans, Merit, entitlement? |
| Data | New entities, retention, residency? |
| Security | Authn/z, abuse, uploads? |
| Privacy | PDPL, minors, minimization? |
| Accessibility | New barriers? |
| Regional policies | `.sa` / `.com` packs? |
| Operations | Admin load, moderation, support? |
| Schedule | Days/weeks to 2029 launch? |
| Cost | Infra, content, vendors? |
| Founder capacity | Fits WIP rule (1+1+1 Spike)? |
| Launch deadline | Compresses MLGW outcomes? |
| Testing | What evidence before merge? |
| Migration | Data/backfill needs? |
| Rollback | How to reverse? |
| External validation | New EXT/TECH IDs? |

## Change thresholds

| Threshold | Definition | Required process |
|-----------|------------|------------------|
| **Minor Scope Clarification** | No Capability or delivery impact | Editorial note; Decision Register if wording mattered |
| **Controlled Enhancement** | Changes one existing Capability without altering MLGW outcomes | Change Request recommended; Gate note |
| **Material Scope Change** | Adds/changes Capability, journey phase, commercial rule, or domain boundary | Formal Change Request + impact analysis + founder approval |
| **Foundational Rebaseline** | Changes identity, Pillars, audience, integrity rules, or launch definition | Foundational CR + Constitution version bump + Scope + Manifest + downstream Gate review |

## WIP reminder

Scope additions must state what they remove, delay, or replace under the founder-capacity constraint in the Scope Baseline.

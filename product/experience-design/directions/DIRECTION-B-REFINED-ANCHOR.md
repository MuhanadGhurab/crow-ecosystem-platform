## Visual thesis

Preserve A’s obsidian–cyan–gold law, but prioritize legible learning structure: clearer regions, calmer density, reusable shells that can scale across five Horizons without becoming a dashboard.

## Spatial composition

| Anchor | Composition |
|--------|-------------|
| **World Portal** | Atmospheric background retained but content band constrained to a readable column; Horizons as a structured world map row with text labels (Operate / Build / Analyze / Protect / Lead — human names only); promise + CTA dominate first viewport |
| **Black Signal** | Split stage: topology (changeable) + decision column; signal feed secondary; RAVEN briefing collapsible; world-state as labeled meters with non-color encoding |
| **Crowprint Debrief** | Structured narrative scroll: outcome → consequence list → Crowprint panel → lineage → Flight Log → Echo / Route; ceremony preserved via spacing and gold edge, not opacity theater |

## Navigation behavior

- Consistent header pattern across authenticated journeys (brand, language, session end) without admin chrome.
- Mission progress as “scene chapter” label + autosave state chip (Synced / Saving / Conflict).
- Debrief uses expand/collapse sections; Crowprint not buried.

## Arabic typography direction

- Stronger type scale (display / title / body / meta).
- RTL grid with consistent inline-start alignment for actions.
- Avoid ornate display that harms 15+ readability.

## English typography compatibility

- Matched scales; English may lead only when locale is EN; never mix hierarchy mid-block.

## Surface hierarchy

1. Primary narrative column  
2. Supporting environment / topology  
3. Status / save / language utilities  
4. Atmospheric remainder  

## Color-role model

Same as A, with increased surface contrast ratios (WCAG-oriented targets for text/buttons). Cyan reserved for interactive focus and live signal; gold only for Crowprint / Horizon ceremony.

## Crow / RAVEN presence

RAVEN as structured brief panel; Crow as restrained mark in debrief — still non-Production art.

## Topology treatment

Simpler topology grammar: fewer nodes, stronger before/after difference, captioned consequence (“continuity rose · evidence thinned”). Topology must update on each decision.

## Mission tension treatment

Tension via content and state change, not visual noise. Signal feed rate-limited visually.

## Crowprint reveal treatment

Panel with clear headings: observed signals · emerging pattern · confidence explanation · **not Mastery / not permanent**. Suggested Lineage below with dismiss.

## Motion language

Shorter durations; purposeful transitions between Mission phases; reduced ambient motion vs A.

## Reduced-motion

Prefer instant region swaps + text announcements; keep topology state text always available.

## Mobile transformation

**Required prototype coverage for B:** Portal and Mission mobile compositions prioritize decision readability; topology becomes compact diagram; feed in bottom sheet.

## Accessibility implications

Best of the three for focus order, landmarks, contrast, and screen-reader labeling of world-state.

## Technical feasibility

**Highest** for Product Code later: maps cleanly to frame/shell seams from preflight; CSS variables + modules; token proposal aligns here.

## Risks

May feel “safer” / slightly more product-like if atmosphere is underplayed; must resist SaaS card creep.

## What makes it uniquely GHURAVIA

Identity laws of A with operational clarity — Living Mission consequence readable in Arabic without engineering chrome.

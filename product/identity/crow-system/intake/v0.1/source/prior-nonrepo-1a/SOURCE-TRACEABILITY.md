## 4. Controlling source precedence

1. Explicit founder decisions and governed repository baselines.
2. Newer explicit founder amendments.
3. Clear carried project constraints.
4. Faithful synthesis of those decisions.
5. Assistant-authored specifications and recommendations.
6. Exploratory images/prototypes.
7. External references used for context.

Rules applied:

- Status follows authority, not filename or heading.
- A newer source changes an earlier decision only when the change is explicit.
- Silence after an assistant specification is not acceptance.
- A prototype proves only what was actually tested.
- A named but undefined field remains undefined.
- A safer privacy boundary controls when an assistant visual suggestion conflicts with an explicit private-data rule.
- External frameworks may validate feasibility; they do not define GHURAVIA taxonomy.

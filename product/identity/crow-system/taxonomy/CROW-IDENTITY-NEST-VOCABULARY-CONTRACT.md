## Purpose

Provide minimum vocabulary so Nest readiness UI cannot be mistaken for Core Crow Lineage award, Prestige, Trust, or Major.

## Binding equalities (must appear in 0E design)

```text
Nest readiness ≠ earned Crow identity
Nest completion ≠ Core Crow Lineage
Nest score ≠ Mastery
Nest score ≠ Trust
Nest score ≠ Cross-Wing Major
Horizon choice ≠ permanent career identity
Wingprint ≠ Lineage
```

## Allowed Nest terms

| Term | Allowed meaning |
|------|-----------------|
| Nest | Onboarding readiness environment / assessment flow |
| Nest readiness / Flight-Ready (working) | Decision that the learner may proceed into Horizon/Route exploration under later Gates |
| Horizon exploration | Choosing or sampling a Horizon without permanent lock |
| Suggested Lineage (if shown) | Non-earned taxonomy suggestion only; must be labeled non-earned |
| Crow personalization | Presentation preference; not Lineage |

## Prohibited Nest claims

| Prohibited claim | Reason |
|------------------|--------|
| “You are now CRW-…” as award | Taxonomy ID is not Nest-awarded |
| “Earned Lineage” from Nest score | Evidence/Mastery lifecycle is 1C |
| Trust meter / flock Trust visual | Trust exclusion |
| Prestige class from Nest | Prestige separate |
| Cross-Wing Major from Nest | Majors not activated |
| Evidence Seal from Nest | Seal ≠ readiness |
| Permanent career assignment | Career-prison risk |

## Copy rules for 0E

1. If a Lineage English name appears, label it **exploratory / not earned** (or equivalent clear language).
2. Horizon selection language must allow later change; no “locked forever” career framing.
3. Result screens must separate readiness outcome from identity taxonomy education.
4. Do not use Flight Signature.
5. Do not invent Evolved Role names.

## Hold release scope

1B releases the **0E governance hold for Nest Intro and readiness decision vocabulary/boundaries only**. It does **not** authorize earned identity runtime, schemas beyond existing Product Code scopes, or taxonomy Product Code implementation.

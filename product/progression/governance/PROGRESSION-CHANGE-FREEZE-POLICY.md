## Purpose

Define what is frozen after successful GHV.PROGRESSION.1D and which change classes apply.

---

## Frozen after 1D

* Progression-system meanings
* Canonical IDs
* Event semantics
* Ledger separation
* Accepted formula versions (per FINAL-FORMULA-VERSION-REGISTRY)
* XP categories
* Momentum architecture
* Maturity dimensions and Rank meanings
* Mastery mandatory floors
* Breadth principles
* Trust non-public model
* Title templates
* Prestige Classes and human authority
* Achievement boundaries
* Leaderboard separation
* Correction mathematics
* Freshness overlays
* Counterfactual-parity requirements
* Anti-pay-to-win invariants

---

## Allowed without Material Change Request (editorial)

* Typographical correction
* Clearer wording without output change
* Reference updates
* Arabic terminology correction
* Accessibility clarification

---

## Requires Controlled Change Request

* Value, threshold, or weight change
* Formula-output change
* Cap or floor change
* Season-duration change
* Event-effect change
* New Achievement
* Leaderboard formula change
* Trust-window change
* Title-template change
* Prestige hard-gate or quorum change
* Closing or altering WITH VALIDATION CONDITIONS without evidence

Controlled CR must: create a new document version; preserve prior baseline history; update Decision Register; update Baseline Manifest / Progression Manifest; update affected formula and simulation records.

---

## Requires Foundational Rebaseline

* Payment influencing progression
* XP becoming Skill
* Popularity becoming Trust
* Evidence-before-Mastery removal
* Automatic Prestige
* Universal Leaderboard
* One Route granting Horizon-Proven

---

## Explicit non-claims

Freeze does **not** mean production calibrated, technically validated, user validated, or implemented.

```text
IMPLEMENTATION: BLOCKED
PRODUCTION READINESS: BLOCKED
REAL-USER CALIBRATION: NOT RUN
TECHNICAL VALIDATION: NOT RUN
```
